## 1. 代码审计（开发前）

| 检查项 | 发现 |
|---|---|
| 本地文件夹 | 用户打开的 `~/Documents/童童乐理空间` 为空，不含仓库 |
| 仓库 | GitHub `atomTONG83/TONGTONG2016-French`（唯一相关仓库），`main` @ `782829e`（2026-09-19），1110 个提交 |
| 托管 | GitHub Pages：`CNAME = tongtong2016.com`、`.nojekyll`；**无** `package.json`、构建脚本、CI、`wrangler.toml` |
| 框架 | 纯静态 HTML + 原生 JS；部分页面用 Supabase REST（`config.js`、`learning_read.js`） |
| 首页 | `index.html` 第一段脚本把访客跳转到 Cloudflare Worker `tongtong-private-staging.euripscope.workers.dev`（统一登录）；首页卡片中 VIOLIN、ENGLISH 等指向 Worker |
| Worker 源码 | **不在本仓库**，也不在可访问的其他仓库；从沙箱无法访问 Worker 页面 |
| 小提琴板块 | `violin_learning_hub.html`：1240 行手写 HTML；含 Web Audio 节拍器、PDF/图片查看器、课程卡片（最新 2026-07-04）。**没有**结构化曲目数据、题目、学习进度机制、乐谱渲染器 |
| 持久化约定 | `/revision/` 复习营：localStorage 单键 JSON（`tt_camp_2026`）+ 导出备份；背单词：Supabase + localStorage |
| 移动端 | 各页有 viewport 与媒体查询；首页尊重 `prefers-reduced-motion` |
| 测试 | 仓库无任何自动化测试 |

### 由审计得出的决策
1. **模块形态**：做成自包含静态目录 `/music-theory/`（与 `/revision/` 同构），零构建、相对路径、哈希路由 → GitHub Pages 与 Worker 静态资源都可直接托管，无需服务器重写。
2. **复用**：沿用原站深色科幻风格方向、原生 JS 写法、`/revision/` 的 localStorage 单键 + 导出备份约定；节拍器思路（Web Audio 定时）与小提琴页一致。小提琴页无结构化曲目数据，因此**不复制曲目库**，只建「曲目 → 技能标签」映射并链接回小提琴页。
3. **不接 Supabase**：写入云端需要新表和权限设计，属于生产数据变更；第一期只做本机存储，并在界面和文档里明确「不跨设备同步」。
4. **乐谱**：原站没有渲染器 → 引入 VexFlow 4.2.3（MIT），本地 vendored，不依赖 CDN。
5. **音频**：Web Audio 自行合成，不引入 Tone.js（体积大、功能用不上）。
6. **测试**：Node 内置 `node:test`，零依赖；端到端用 Playwright 脚本（不写入依赖）。

## 2. 架构

```
music-theory/
├── index.html            外壳：顶栏、返回链接、加载 VexFlow 与 main.js
├── css/quest.css
├── vendor/vexflow-bravura-4.2.3.js (+ LICENSE)
└── js/
    ├── theory.js         乐理规则（纯函数，可单测）
    ├── violin.js         指板规则（纯函数，可单测）
    ├── store.js          学习记录 / 间隔复习 / 统计（可注入 storage 与时钟，可单测）
    ├── audio.js          Web Audio
    ├── main.js           哈希路由
    ├── content/          题库与关卡（答案全部由 theory/violin 计算）
    │   ├── port.js       世界1 五线谱启航港
    │   ├── towers.js     世界2 升降号魔法塔
    │   ├── arena.js      世界3 节奏竞技场（含敲击评分 scoreTaps）
    │   ├── lab.js        世界4 指板实验室
    │   ├── forest.js     世界5 听觉森林
    │   ├── castle.js     世界6 独立识谱城堡（识谱侦探）
    │   ├── tasks.js      老师任务 + 曲目技能标签
    │   └── index.js      技能表、题库注册（稳定 ID）、世界与关卡
    └── ui/               dom / staff / widgets / question / rhythm / detective / pages
```

**答案真值原则**：所有正确答案由 `theory.js` / `violin.js` 的确定性规则计算；人工写下的核对值（还原号情境 `expect`、侦探乐谱 `expect`/`string`/`finger`）在单元测试中与规则结果逐一比对，二者不一致即测试失败。没有任何答案来自生成式文本。

10. 写交接文档、本记录、更新日志；本地提交。

## 6. 独立审阅

由一个未参与编写的审阅代理通读全部题库与规则文件，检查乐理/指法正确性、歧义、干扰项、法语术语。结果与处理见下（交付前补记）。

**结论**：全部 347 题的标准答案均正确，没有「干扰项其实也对」的情况；8 段侦探乐谱的音高、琴弦、指法、每小节拍数全部正确；法语术语拼写正确。

审阅提出的问题及处理：

| # | 审阅意见 | 处理 |
|---|---|---|
| 1 | **八度编号**：应用原用国际科学记法（中央 Do = Do4、La4 = 440），法国音乐学院习惯是中央 Do = Do3、La3 = 440，会与老师说法冲突 | **已改**：所有孩子看到的八度号改为法国习惯（空弦 Sol2–Ré3–La3–Mi4）；程序内部仍用科学记法（MIDI 60 = C4），`frenchOctave()` 统一换算；新增测试防回归 |
| 2 | Becker《Gavotte》：小提琴页写「B♭ 大调（双降号）」，同页老师笔记却提到 ♭La（不在 B♭ 大调中）、并有「G 大调段」，信息自相矛盾 | **已改**：乐理题讲解和关卡说明中不再引用该曲的调性；曲目标签处注明「调性待按乐谱核对」。原小提琴页内容未改动 |
| 3 | 第三把位「往上数第 4 个音名」可能被理解成从空弦之后再数 4 个 | **已改**：统一写成「空弦本身算第 1 个……也就是第一把位 3 指的位置」 |
| 4 | 升号顺序口诀「每次往上数 5 个音名」同样有歧义 | **已改**：「从这个升号算起，数到第 5 个音名」并给出两组示例 |
| 5 | 侦探「独立再读」干扰项出现 Mi♯、Si♯、Fa♭、Do♭ 等罕见拼写 | **已改**：只用常见拼写（如 Mi/Mi♭、Do/Do♯）；新增测试 |
| 6 | 两道排序题对「看节奏」的位置不一致（一个放最后，一个放第二） | **已改**：「开拉前」题改为「看调号和拍号 → 把音名、节奏都读一遍 → 摆好姿势 → 数一小节」，与解码顺序不冲突 |
| 7 | 全音/半音讲解「手指靠拢/分开」在涉及空弦时不成立 | **已改**：限定为「在同一根弦上用相邻两根手指时」 |
| 8 | 节奏多敲提示总是提 blanche，即使节奏型里没有 | **已改**：按节奏型给提示 |
| 9 | clé de fa 干扰项可补充说明 | **已改**：讲解中补充「clé de fa 标的是第四线 Fa」 |
| 10 | 大调首字母大写、小调小写，风格不一 | 保留：大调名称单独作为选项标签出现，首字母大写可读性更好；不影响正确性 |
